title: "Transaction webhooks"
description: "Version 2 transaction lifecycle events, payment review, refunds, and cancellation."
---

Transaction events track every observable status transition, including transfers, deposits, and withdrawals. Subscribe to reconcile funding and settlement without polling.

## Version 2 payload

New `transaction.*` events use `payloadVersion: 2`. Their `data` contains:

- `transaction`: the transaction **after** the transition, including its public status, amounts, chain, timestamps, and any queued `withdrawalRequest`;
- `previousStatus`: the previous observable status, or `null` for a first event or a transition out of the internal `created` / `claimed` states. Internal states never emit events.

The transaction summary uses camelCase keys and includes nullable keys explicitly as `null`. It does not duplicate the nested `account` object returned by transaction queries; `accountId` remains available.

<Warning>
  Dispatch by both event type and `payloadVersion`. Customer and test events remain at version 1. Previously stored payloads are not rewritten when retried: old version 1 transaction deliveries may still arrive.
</Warning>

Each transaction event sets `transactionId` and `accountId` in `related`. The other three routing keys are `null`.

## Event types

| Event | Observable status |
| --- | --- |
| `transaction.withdrawal_initiated` | A signed withdrawal is queued pending vault liquidity. |
| `transaction.waiting_for_funds` | The transaction is waiting for funds. |
| `transaction.payment_in_review` | The payment is under review. This is not a completed payment. |
| `transaction.funds_in_transfer` | Funds are being transferred. |
| `transaction.funds_received` | Funds have been received. |
| `transaction.processing` | The transaction is being processed. |
| `transaction.completed` | The transaction completed successfully. |
| `transaction.simulation_failed` | Transaction simulation failed. |
| `transaction.reverted` | The on-chain transaction reverted. |
| `transaction.refunded` | The payment was refunded. |
| `transaction.cancelled` | The queued withdrawal was cancelled. |

An event reports a persisted transition, not a promise that every transaction passes through every status. For status meanings and polling, see [Tracking transactions](/api-reference/tracking-transactions).

## Reconciliation and replay

Verify signatures against the exact raw request body, acknowledge deliveries idempotently, and deduplicate by the event `id`. Delivery order should not be used as your only source of truth: retries can arrive after later events. Query the current transaction when reconciling its latest state.

`GET /v1/query/events` exposes the same persisted lifecycle envelope with an additional `createdAt`. Replays and delivery retries retain the original payload version. See [Webhook delivery and signatures](/api-reference/webhooks/overview).
