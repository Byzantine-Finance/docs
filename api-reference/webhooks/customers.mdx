---
title: "Customer webhooks"
description: "Customer onboarding (KYC/KYB) lifecycle webhook events."
---

Customer events track the KYC/KYB onboarding lifecycle of a customer. Subscribe to them to keep your onboarding UI and compliance workflows in sync.

## Populated fields

Every customer event carries the ids it concerns in the envelope's `related` block. `accountId` is always set, together with `userId` for an individual customer or `entityId` for an entity. `beneficiaryId` is set when the event concerns one specific associated person of an entity. Keys that do not apply are `null` rather than absent.

## Event types

| Event | Fires when |
|-------|------------|
| `customer.created` | An individual/entity account is created (KYC/KYB submission started). |
| `customer.under_review` | KYC/KYB is in progress. |
| `customer.awaiting_associated_person_information` | An entity customer is waiting for a beneficiary's or representative's information. |
| `customer.resubmission_requested` | Additional information or documents are required from the customer. |
| `customer.active` | Verification is approved; the account can transact. |
| `customer.rejected` | Verification was rejected. |
| `customer.deactivated` | A previously active customer was deactivated and can no longer transact. |

For the full meaning of each state, see [Verification statuses](/api-reference/verification-statuses).

## The `data` object

Every `customer.*` event carries the same three keys under `data`. All three are always present - they are set to `null` when they do not apply, so a strict schema validator never sees keys appear and disappear between event types.

| Key | Set when | Contents |
| --- | --- | --- |
| `customer` | Always | The KYC/KYB subject: `accountId`, `customerType` (`individual` or `entity`), `userId` **or** `entityId`, `name`, `email`, `verificationStatus`, `createdAt`. |
| `beneficiary` | UBO-scoped events only | The associated person the event is about: `beneficiaryId`, `firstName`, `lastName`, `verificationStatus`. `null` otherwise. |
| `reasonCodes` | `resubmission_requested` and `rejected` | Array of reason codes explaining the decision. `null` otherwise. |

<Note>
`name` is `"FirstName LastName"` for an individual and the company name for an entity. `email` is the user's email for an individual, or the company email declared at KYB for an entity - `null` when the entity declared none.
</Note>
